Narad

A governed intelligence layer for multi-agent systems. It works like a nervous system for coordinating many agents: every external action passes a policy gateway first, and every answer arrives with its lineage.

Open the live console

The idea

A nervous system, with a gate at the edge

Give several agents the same outside world and the failure mode is predictable: one of them runs an expensive crawl nobody approved, or a wide-reaching action nobody can trace back. Narad puts the governance at the edge, in front of the work. Agents cannot spend compute or touch the outside world until a policy rule has said yes, and the policy check runs before any compute is spent.

State lives in one place, a single Postgres database holding the entity graph, the research runs, the vectors, and the ledger of policy decisions and approvals. Vectors, documents, and the entity graph share one transaction boundary, so a rollback can never leave a vector pointing at a document that does not exist.

The default policy is plain: no research into personal data about private individuals, agents may not use the pro or ultra processors, and multi-hop crawls or forced refreshes go to a human approval queue. Only human reviewers can clear that queue, and they cannot approve their own requests.

Detail

At a glance

StackFastAPI, Pydantic, asyncpg, Postgres 16 with pgvector, Docker, Railway.
PolicyPolicy-as-code in policies/default.yaml. First matching rule wins: allow, deny, or review. API keys are stored only as SHA-256 hashes.
MemoryOne Postgres database for entities and graph edges, JSONB runs with citations, pgvector chunks with an HNSW index, and the policy, approval, and event ledger.
Execution meshParallel.ai Task API with a strict output JSON schema and field-level citations. A mock mesh gives clearly labelled synthetic data for offline work.
EmbeddingsAny OpenAI-compatible embeddings endpoint, or a deterministic offline hash embedder.
APIPOST /v1/intel, GET /v1/approvals, POST /v1/approvals/{id}/decision, GET /v1/events, /v1/stats, /v1/search, /healthz, /v1/meta.
LiveDemo on Railway at narad-production-b7dd.up.railway.app. In-memory state, mock mesh, hash embedder, and state resets on redeploy. The production path is Postgres 16 with pgvector, set as DATABASE_URL on the gateway service.
